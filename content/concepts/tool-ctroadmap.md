# CTRoadmap

一个**本地优先**的基础设施图谱工具——用 **GUI** 把节点、服务、存储、脚本、配置、URL 和运维关系**画成可视化磁贴 + 连线**记下来；**数据存成本地 `atlas.json`**，**不执行任何命令、也不做实时探测**。

## 它是什么

- 一款**纯绘图 / 文档化**性质的基础设施关系工具；
- 和"自动发现型"工具（如 NetBox、CodiMD、k8s 集群探针）相反——**全靠人手动摆磁贴、连关系**；
- 本地优先：单一 JSON 文件为真相源，方便版本控制、备份、二次加工。

## 关键能力

| 能力 | 说明 |
|------|------|
| 磁贴画布 | 节点 / 服务 / 存储 / 脚本 / 配置 / URL 都作为磁贴 |
| 关系连线 | 画"谁调谁、谁依赖谁、谁部署到谁" |
| 本地存储 | 数据 = 单一 `atlas.json` |
| 零执行 | 不会 ssh 进去拉数据，也不会调云 API |
| 零探测 | 不发心跳、不探活、不画实时状态 |
| 离线可用 | 装上就能用，不依赖云服务 |

## 为什么用它 / 适合什么场景

- **架构图 / 依赖关系图**用 draw.io / Miro 画太重，又不便于 diff / review——它用 JSON 替代画图文件，可纳入 Git；
- 团队**没有自动发现工具**，但又需要一份"我们到底跑了些啥"的图——手动建一次，受益多年；
- 离线 / 隔离网络 / 涉密环境——不能装自动发现 agent，但还是要画清楚关系。

## 适合放的磁贴类型

- 物理节点 / 虚拟机 / 容器
- 微服务 / 后台进程
- 数据库 / 缓存 / 对象存储
- 运维脚本 / 定时任务
- 配置文件 / 环境变量
- 内外部 URL / API 入口

## 与"自动发现"工具的差异

| 维度 | CTRoadmap | NetBox / 自动发现类 |
|------|-----------|---------------------|
| 数据来源 | 人工 | 自动探活 + 人工校对 |
| 准确性 | 看人 | 看探针 |
| 维护成本 | 高 | 中 |
| 离线可用 | ✅ | ❌（通常需联网） |
| 可版本控制 | ✅（JSON） | ❌（数据库） |
| 实时性 | ❌ | ✅ |
