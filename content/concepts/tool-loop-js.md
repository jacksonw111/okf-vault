# loop.js

给 **loop.js** 一个**目标**和**"怎样算做完"的标准**，它就一轮轮驱动 **agent** 往下干——**每轮清空上下文**、**把笔记存盘**，直到一个**独立且默认只读的 Verify** 判定达标才罢手。

**目标、执行、验证**三件事在 loop.js 里都是**同一种 prompt**，但**验证权**只在**独立的 Verify agent** 手里，干活的 worker **没有自判权**。

## 它是什么

- 一个**长任务循环执行框架**——把"AI 干一长串事"拆成**多轮 worker 循环**；
- 每轮 worker 跑完就把上下文**清空 + 笔记存盘**——避免上下文膨胀；
- 独立的 **Verify agent** 默认只读地判定"这一轮是否达标"，**达不上标准循环不止**；
- 关键的工程取舍：**worker 不自评**，避免"自己说自己做好了"；
- 三件事（目标、执行、验证）都是**同一个 prompt 语法**——一套接口学三处。

## 关键能力

| 能力 | 说明 |
|------|------|
| 目标驱动 | 用户只给"想达成什么"+"怎样算达成"，不写步骤 |
| 多轮 worker | 自动多轮执行，每轮从盘上恢复状态 |
| 每轮清空上下文 | 防上下文膨胀，强制 worker 靠"笔记"持续工作 |
| 笔记存盘 | 每轮产生的中间产物 / 计划落盘 |
| 独立 Verify | 另起一个**默认只读**的 agent 评判 |
| Worker 无自判权 | 工人不能自己给自己打勾 |
| 同构 prompt | 目标 / 执行 / 验证都共用一种 prompt 写法 |

## 为什么用它 / 适合什么场景

- 跑**长链 AI 任务**（代码迁移、大批量文档整理、跨多文件的重构）——单轮 context 装不下；
- 担心 **agent 自评自夸**——把判定权**显式分给另一个 agent**；
- 想让 **worker 靠"持久笔记"工作**而不是靠"context 累积"——更接近人脑的工作方式；
- 需要**可审计**的 agent 循环：每轮做了什么、有没有改进，笔记都是盘上文件；
- 想给**多 agent 协作**设计一套**简单一致的接口**——同一种 prompt 描述目标、执行和验证。

## 核心机制：三角色同构 prompt

```
┌──────────────────────────────────────────────┐
│              loop.js 控制循环                 │
└──────────────────────────────────────────────┘
        │                  │                │
        ▼                  ▼                ▼
  ┌──────────┐       ┌──────────┐     ┌──────────┐
  │   目标    │       │   执行    │     │   验证    │
  │  Goal    │       │  Worker  │     │  Verify  │
  │ (prompt) │       │ (prompt) │     │ (prompt) │
  └──────────┘       └──────────┘     └──────────┘
                          │                │
                          ▼                │
                  笔记存盘 ←────────────────┘
                  (worker 经验)        (只读，不写)
```

- **Goal**：描述最终目标 + 完成标准
- **Worker**：执行当前轮，产出笔记
- **Verify**：默认只读，判定 Worker 这轮达没达标；不达标 → 触发下一轮 Worker

## 设计哲学

1. **目标导向**——给"想要什么"和"怎样算完"，别写"怎么一步步做"；
2. **清空即纪律**——每轮清空上下文逼迫 worker 用笔记而不是 context 续命；
3. **验证独立**——自己说自己行不算数；
4. **同构 prompt**——少学一套语法，三处通用；
5. **笔记即历史**——盘上文件天然可审计、可回溯。
