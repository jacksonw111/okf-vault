# agentic-mercy-10x

一套**面向 Claude Code 的发行版**——用**单一路由器**把每次提示派发给对应的**技能 / 专家**，并在**写入时通过钩子强制代码规范、测试与安全门禁**。

## 它是什么

- 一个**Claude Code 的"加固版"发行包**——不是单点工具，而是整套治理；
- 引入**路由器**：每次进来 prompt 先路由到合适的**技能 / 专家**（specialist）再执行；
- 引入**写入钩子（hooks）**：任何写到仓库的修改都必须先过规范、测试、安全三道门；
- 适合团队 / 个人把"Claude Code 帮我干活"变成"**Claude Code 在我的规则里干活**"。

## 关键能力

| 能力 | 说明 |
|------|------|
| 单一路由器 | 把每次 prompt 分派到匹配的技能 / 专家 agent |
| 专家池 | 内置或可挂载的 specialist 角色（重构 / 测试 / 安全 / 文档……） |
| 写入钩子 | 在文件落盘前拦截，按规则校验 / 修正 / 拒绝 |
| 规范门禁 | 强制代码风格、命名、目录约定等 |
| 测试门禁 | 改动必须配套 / 不破坏既有测试 |
| 安全门禁 | 拦截危险命令、敏感路径、密钥外泄等 |
| 审计 | 钩子全过日志，方便事后审查 |

## 为什么用它 / 适合什么场景

- 团队里**多个开发都在用 Claude Code**，但**风格 / 安全规则五花八门**——本工具把这些规则**集中到钩子里**强约束；
- 想让 Claude Code **自己挑技能**而不是每次手挂 SKILL——路由器自动派单；
- 担心 Claude Code **误改生产文件 / 把密钥写到代码里 / 跑 rm -rf**——写入钩子在落盘前先审；
- 在做**"AI 编码 + 合规"**的实验：把公司安全策略、测试覆盖率门槛、代码规范全部塞进钩子；
- 想把 Claude Code **从"个人玩具"升级成"团队基建"**——分发一套发行版给所有成员。

## 架构速览

```
          用户的 prompt
                │
                ▼
       ┌──────────────────┐
       │   路由器（核心）   │  ← 按意图 / 上下文路由
       └──────────────────┘
                │
   ┌────────────┼────────────┬──────────────┐
   ▼            ▼            ▼              ▼
重构专家     测试专家     安全专家        文档专家
                │
                ▼
       ┌──────────────────┐
       │  写入钩子（落地）   │  ← 规范 / 测试 / 安全 三道门
       └──────────────────┘
                │
                ▼
              文件系统
```

## 设计哲学

1. **路由 + 治理**——既能派活，也能守门；
2. **钩子在写入时**——审在落盘前，不靠事后 review；
3. **规则集中**——规范 / 测试 / 安全策略都集中在一处，便于维护；
4. **Claude Code 是底座**——所有能力都基于 cc 扩展，不重新发明轮子。
