# 主中 + 顶 header + 单侧栏：实用三段布局

## 一句话

**主内容放中间、主内容的状态放顶部 header、临时辅助内容放单个侧边栏**——三段就够，不要双侧栏。

## 布局示意

```
┌──────────────────────────────────────┐
│   Header（主界面状态、用户、设置）    │  ← 全局信息密度高
├────────────┬─────────────────────────┤
│            │                         │
│  Sidebar   │   Main Content          │  ← 主要操作在这里
│ （临时辅助）│  （用户的主要工作区）   │
│            │                         │
└────────────┴─────────────────────────┘
```

## 三条原则

1. **主内容 = 中**——用户的「主任务」永远在主区域，不要被工具栏挤到角落。
2. **顶部 header = 主界面状态**——用户身份、当前项目、保存状态、搜索、通知等**全局上下文**才上 header；不是主界面状态的不要进 header。
3. **侧边栏 = 临时辅助**——只放「短时用、随时可关」的内容（评论、详情、过滤器、历史记录），且**只一个就够**。

## 为什么避免双侧栏

| 双侧栏 | 单侧栏 |
|--------|--------|
| 用户被左右两边的内容夹击，注意力被切碎 | 中间主区域净空，焦点清晰 |
| 屏幕宽度被切到 < 800px 时两侧栏挤占主区 | 单侧栏可折叠，主区始终有 ≥ 60% 宽 |
| 左侧 nav + 右侧 props 是 IDE / 桌面工具的范式，但常带来「工具压人」感 | 临时辅助按需弹出，更轻 |

## 信息密度分布

> 信息密度从左往右逐级展开

- **最左（sidebar）**——密度**低**：临时辅助 / 上下文
- **中间（main）**——密度**高**：实际工作内容
- **顶部（header）**——密度**最高**：全局状态、关键操作

## 适用场景

- 后台 / Dashboard
- 笔记 / 阅读应用（Notion / Linear 风格的 main + sidebar）
- 文档 / Wiki
- Agent / CLI 工具的桌面 GUI

## 不适用场景

- IDE（确实需要双侧栏：左边文件树、右边 outline）
- 复杂数据可视化（多面板同时显示）
