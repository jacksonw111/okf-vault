# exxperts

一个**跑在你自己的机器上**的 AI 智能体运行时，核心卖点是**"记忆房间"（memory rooms）+ 写盘前必须用户批准**——把"AI 长期记忆"这件事做成本地、可审计、可回滚的事。

## 它是什么

- 一个本地 AI agent 运行时（不是 SaaS，云端无关）；
- 引入 **"记忆房间"** 的概念：把不同主题/项目/对话的长期记忆分房间隔离；
- 每次 agent 准备往记忆里**写新东西**时，会停下来等**用户显式批准**——不允许 agent 静默改写它的长期记忆；
- 所有数据都是你硬盘上的文件（看得见、删得掉、可 grep）。

## 关键能力

| 能力 | 说明 |
|------|------|
| 记忆房间 | 跨会话、按主题/项目隔离的长期记忆 |
| 写盘审批 | 每次记忆写入前必须用户同意（人工在环路） |
| 本地优先 | 数据全部以本地文件落地，不上传 |
| 可审计 | 文件即记忆，文本可读，diff 可看 |
| 跨会话 | 不同 session 共享同一份记忆 |

## 为什么用它 / 适合什么场景

- 想让 AI 长期记住你**和你的工作**（项目背景、决策、术语），又不想把这些塞给云端；
- 担心 agent **悄悄往自己的 memory 里塞东西**——这个工具强制每次写入都问一句"你确定吗？"；
- 希望 agent 的"记忆"对你**透明、可编辑、可回滚**，而不是被锁在某个向量数据库里；
- 内部 / 隐私敏感项目（金融、医疗、企业内部知识）需要本地部署。

## 设计哲学

1. **Memory 是数据，不是魔法**——能落成文件、被人审阅。
2. **写动作不可静默**——agent 想改自己的记忆必须问。
3. **房间化隔离**——不同工作用不同记忆，避免串味。
