# Machinexis（设备→传感器→告警→工单多租户平台）

## 它是什么

`Itachi7011/Machinexis` 是一个面向设备运维场景的多租户管理平台，把「设备 → 传感器读数 → 阈值规则 → 告警 → 工单」这条原本散落在带签 Excel / 多套系统的链路，收敛进同一个 SaaS 形态的平台。读数越界自动产生告警，告警可一键转工单并跟踪到关闭。

> ![](https://pbs.twimg.com/media/HPpftySa0AATDzv.jpg)

## 为什么用它 / 适合什么场景

- **多设备、多租户**：工厂 / 物业 / 设备服务商等场景下，几十上百台设备、多个客户必须物理 / 逻辑隔离。
- **替代带签表 + Excel**：原流程靠人把抄表数据转写到多套系统，错误率高、追溯难。
- **告警到工单闭环**：以前「超阈值」只发短信 / 邮件，常常没人跟进；现在直接落到工单并指定负责人。

## 关键能力

| 能力 | 说明 |
|------|------|
| 设备管理 | 录入设备、绑定传感器、设置元数据（位置 / 责任人 / 维保期） |
| 传感器读数接入 | 接收 MQTT / HTTP 等协议上报的读数 |
| 规则引擎 | 阈值 / 区间 / 趋势多种触发条件 |
| 告警自动产生 | 越界 → 告警 → 通知（站内 / 邮件 / Webhook） |
| 工单一键转 | 告警 → 工单，自动带上下文（设备 / 读数 / 历史） |
| 多租户隔离 | 每租户独立的数据 / 用户 / 配置 |
| 维护数据可追溯 | 告警 / 工单 / 处理记录全在一个时间线上 |

## 工作流

```
传感器读数上报 → 规则引擎匹配 → 自动告警
                                    ↓
                          负责人确认 / 派单
                                    ↓
                          一键转工单 → 处理 → 关闭
                                    ↓
                          历史归档（设备维保档案）
```

## 适用人群

- 工厂 / 楼宇 / 物业的设备运维团队。
- 工业 IoT 集成商（要给多个客户部署）。
- 任何「设备多 + 抄表 + 跟进」还停留在 Excel + 微信群的企业。
