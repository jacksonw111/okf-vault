> Claude Code 스타트업 가이드
> 
> 앤트로픽에서 여러개의 고성장 스타트업을 인터뷰해 정리한 가이드예요.
> 
> 📑 PDF - Claude Code Guide For Startups
> https://cdn.prod.website-files.com/6889473510b50328dbb70ae6/6a85f3ce3623355a8a44ca36_Claude_Code_Guide_For_Startups_Final_web.pdf
> 
> 중요한건 이거예요. 이들이 Claude Code를 SDLC 전 과정에 깊게 통합해 자기 규모보다 10배 큰 조직처럼 제품을 출시하고 있다는 것!
> 
> 규칙 살펴보면 이래요.
> 
> 1. 모두가 출시한다 = mcp + connect + cli 도구가 토큰 효율 더 좋을 수 있음
> 
> 에이전틱 코딩은 진입장벽을 낮춰, 코딩을 몰라도 문제를 가장 잘 아는 사람이 첫 버전을 직접 만들 수 있게 함.
> 
> 팀 표준은 재사용 가능한 스킬로 공유.
> 
> ↓
> 
> 2. 반복 업무 자동화
> 
> 에이전트가 기계적인 80%를 담당해 엔지니어는 판단이 필요한 부분에 집중하자.
> 
> AI 네이티브 SDLC.. 그리고 데이터 분석이 가장 흔한 사례.
> 
> Dynamic workflows로 서브에이전트 병렬 실행할 수도.
> 
> ↓
> 
> 3. 신뢰하되 검증하자
> 
> 자동화하려면 반드시 검증 수단이 필요. 어느 스타트업도 무작정 main에 머지하지 않음!
> 
> 특정 사례가 아닌 일반 원칙을 고칠 것!
> 
> CLAUDE.md에 변하지 않는 규칙 명시.
> Hooks는 결정론적 하드 게이트.
> Loops는 명확한 종료조건이 있을 때 효과적.
> 
> ↓
> 
> 4. 재구축을 전제로 만들자
> 
> 모델 능력이 계속 바뀌므로 영구적인 것은 거의 없다는 철학.
> 
> git worktree로 v1을 유지한 채 v2를 별도 브랜치에서 병렬 구축, 평가 후 이긴 쪽만 머지
> (재구축 저렴하게 만드는 핵심 기법)
> 
> ↓
> 
> 5. 프로토타입 → 내부사용 → 제품화
> 
> Claude Code로 실력을 쌓으면 그 인사이트가 자사 제품에도 반영되는 선순환 구조.
> 
> 패턴: 내부 에이전트 구축 → 내부 사용 → 반응 좋으면 Claude API/SDK로 고객 대상 제품화
> 
> 앞으로도 Claude Code와 같이 잘 먹고 잘 살자..
