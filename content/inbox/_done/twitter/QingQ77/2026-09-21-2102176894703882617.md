> 转发内容

> 现在 Coding Agent 越用越多，但有个问题一直没解决：
> 
> Claude Code 学会的东西，换到 Codex 或 Cursor 后，基本又得重新来一遍。
> 
> Agent Beacon 做的就是这一层。
> 
> 它会把不同 Agent 的完整 session history 收集起来，再把里面有用的调试路径、修改习惯、项目规则和纠错记录提取成可以复用的知识。
> 
> 目前支持 Claude Code、Cursor、Codex、OpenCode、Cline、Hermes、Pi、Gemini CLI 等 20+ Agent / harness。
> 
> 它主要做几件事：
> 
> >把不同 Agent 的历史统一成一套格式
> >记录 prompt、response、tool call、command、文件修改、审批、MCP、token 使用
> >可以完整回放一次 Agent session
> >从历史会话里提取可复用的项目知识
> >通过 MCP 或 Agent Skills 再提供给后面的 Agent
> >默认本地写入 JSONL，不强制绑定某个 Agent 平台
> 数据模型基于 OpenTelemetry。
> 本地可以直接看：
> beacon traces
> 或者打开 dashboard：
> beacon endpoint dashboard
> 
> 底层原始记录也直接放在：
> 
> ~/.beacon/endpoint/logs/runtime.jsonl
> 
> 除了本地，它还能把同一份 Agent telemetry 发到 Splunk、Datadog、Elastic、Sentinel、S3、GCS、CloudWatch 等现有日志系统里。
> 我觉得它比较实际的一点是：
> 它把“Agent Memory”和“Agent 可观测性”放在了一起。
> 
> 你不仅能让下一个 Agent 复用之前踩过的坑，还能知道之前那个 Agent 到底执行了什么命令、改了什么文件、调用了哪些工具、花了多少 token。
> 
> 对同时用 Claude Code、Codex、Cursor 这类工具的人来说，这比给每个 Agent 单独维护一套 Memory 更省事。
>
