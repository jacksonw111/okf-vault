> I've been building my own coding agent from scratch.
> 
> Here's one thing I've learned so far:
> 
> The LLM is probably the smallest part of a good AI agent.
> 
> The actual engineering happens around it.
> 
> The core agent loop is surprisingly small.
> 
> Reason → Act → Observe → Repeat
> 
> The model:
> 
> • Reasons about the goal
> • Picks a tool
> • Gets the result back
> • Continues until it decides the task is complete
> 
> But that loop alone doesn’t give you a production-ready agent.
> 
> You still need to control:
> 
> 1. What context reaches the model and how it gets compressed.
> 2. Which tools the model can access and how it uses them.
> 3. Which actions can run and which need approval.
> 4. Where tools execute, how memory persists, and how you operate sandboxes and subagents.
> 5. How you trace, debug, test, and validate failures and results.
> 6. How the final result gets returned to the user.
> 
> And then there’s the infrastructure supporting all of this:
> 
> • Observability and tracing via Opik by @Cometml 
> • Hosting open models via @modal 
> • Remote sandboxing via @modal 
> • AI eval harnesses via Kitaru by @zenml_io 
> 
> The surrounding system is the agent harness.
> 
> For Decode (my coding agent), the tool-calling agent is ~20 lines of Pydantic AI.
> 
> Everything else around it is the harness.
> 
> LangChain showed this nicely on Terminal-Bench:
> 
> Keeping the model fixed and changing only the harness moved their coding agent from roughly 30th place into the top 5.
> 
> This is why Harness Engineering is becoming one of the most important skills for AI Engineers.
> 
> You’re engineering the system around it so the model can reliably do useful work.
> 
> I break down the complete system design behind Decode in the first article of my Building a Coding Agent From Scratch course.
> 
> Read it here: https://www.decodingai.com/p/building-a-coding-agent-from-scratch-system-design
